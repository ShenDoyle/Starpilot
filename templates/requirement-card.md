# 需求卡片

> 用法：激活星舵 skill 后，先读完全部上下文，再填这张表 → 拿表跟用户确认 → 用户明确通过才进规划。
> 纪律：**只写事实，不写判断**。禁止出现「我理解你大概是想……」「建议顺便也做……」。
> 落盘位置：`<项目>/docs/requirements/<需求名>.md`

## 二、未明确

> 判定标准：**有两种以上合理解读**就属于这里。每条写清「不同答案会导致什么不同做法」——这是用户能快速做决定的关键。

| # | 待确认点 | 方案 A | 方案 B | 不同答案的影响 |
|---|---|---|---|---|
| 1 | | | | |

**清空条件**：这一节全部清空（用户逐条回答过，或明确说「按你判断的来」）才允许进 §3 规划。
**禁止**：在需求没定型时去问网页版 AI——那等于让它替你猜用户要什么。

## 五、确认记录

| 轮次 | 日期 | 用户回复 | 确认状态 |
|---|---|---|---|
| 1 | | | 待确认 / 已确认 / 部分确认（不算通过） |

> **通过标准**：用户明确说「就这样」「开始」「没问题」之类。
> **用户沉默或只回答部分问题，不构成通过。**

---

## 六、成熟度分流

| 情况 | 判定 | 下一步 |
|---|---|---|
| 需求几乎完善 | 「未明确」很少，「有冲突」已核 | 确认后直接进规划 |
| 只有初步想法 | 「未明确」很长 | **逐条问**，问完再进规划 |
