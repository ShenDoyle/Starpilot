# 网页 AI 记忆自测表

> 用途：判断某个网页版 AI 到底能不能当星舵的规划者。**别信评测，信自己这一轮。**
> 耗时约 20 分钟。跑完把结论回填 `scripts/platforms.py` 的 `notes`。
> 单个平台一份，本表可复制多份。

## 1. 精确串埋点（第 1 轮埋，第 6/12 轮查）

第 1 轮同时埋下四种精度的东西：

| 类型 | 示例 | 检查什么 |
|---|---|---|
| 无意义随机串 | `ZQX-7741-KERNEL` | 有没有被**原样**记下来（最能暴露压缩） |
| 路径 | `runtime/wa/turn-007.md` | 路径分隔符有没有被改写 |
| 规则编号 | `R-47` | 编号有没有被说成别的 |
| 变量名 | `before_msgs` | 下划线、大小写有没有丢 |

> 随机串是最好用的探针：**它没有语义，模型只能靠记忆或复制**。第 10 轮还能原样说出 `ZQX-7741-KERNEL`，说明早期上下文还在；说不出，说明已被压缩或丢掉——但注意这可能是**压缩**也可能是**截断**，两者要分开判断（见第 4 步）。

## 3. 精确措辞保真测试（第 11 轮）

第 11 轮问：「把你之前定的那份字段清单原样列一遍，不要改写、不要解释」。

| 检查 | 通过 |
|---|---|
| 字段名逐字一致（无改写、无增删） | ☐ |
| 顺序没变 | ☐ |
| 没有加解释性文字 | ☐ |
| 数量与第 1 轮一致 | ☐ |

> 这一步专抓「**摘要延续**」：大意对但措辞变了。摘要型平台的典型表现就是这一栏大面积不过。

---

## 4. 区分「压缩」还是「截断」（第 12 轮）

第 12 轮问两个问题：

**问题 A**：「我们最开始约定的那个随机串是什么？」
→ 答不出 = 早期内容没了

**问题 B**：「这轮对话一开始的第 1 条，你还能复述大概意思吗？」
→ 答不出 = 更早的开头被**截断**了
→ 能答出大概意思但答不出精确串 = 早期内容被**摘要压缩**了（还在，只是模糊）

| A | B | 判定 |
|---|---|---|
| 能答出 | 能 | 记忆完好 |
| 能答出 | 答不出大概意思 | **截断**（上下文窗口硬上限） |
| 答不出 | 能答出大概意思 | **摘要压缩**（早期细节被模糊化） |
| 答不出 | 答不出 | 上下文已清空/换过对话 |

> 这个区分决定了对策：**截断**只能换窗口更大的平台或分段；**摘要压缩**可靠落盘 + 重贴结论缓解。

## 5. 输出格式稳定性（第 13 轮）

贴一份 `templates/feedback.md` 的模板骨架，让它按格式填。

| 检查 | 通过 |
|---|---|
| 六段都在（状态/做了什么/证据/数据/问题偏差/下一步裁定） | ☐ |
| 没有多余的自由发挥段落 | ☐ |
| 数据表保留了「出处」列 | ☐ |
| 没把证据写成「测试通过」这种空话 | ☐ |

> 塌格式 = 每次反馈都要人工重排，星舵的自动化收益直接归零。**这一项不通过就不用考虑这个平台了。**

| 检查 | 通过 | 说明 |
|---|---|---|
| 有输入框且能接收长文本 | ☐ | 贴 5000 字不截断 |
| 有明确的「发送」按钮 | ☐ | 星舵要点它，不是按回车 |
| 有「生成中」状态可判 | ☐ | 停止按钮或等价信号 |
| 回复能完整读出来 | ☐ | |
