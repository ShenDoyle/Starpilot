# 内置浏览器模式（builtin 后端）

> 0.1.6 起支持。很多宿主 agent 自带浏览器能力（WorkBuddy browser-use、playwright-cli、
> 宿主内置 Chrome 控制等），bsk 不再是唯一路径。选了 builtin：**不装 bsk、不装扩展，
> 脚本完全不碰浏览器**；发送、读取、等待、分诊由 agent 用自己的浏览器工具按本规程执行。

---

## A. 什么时候选 builtin

> **先分清三条路**：bsk（全自动，要装依赖）· IAB 传输层（`STARPILOT_TRANSPORT=iab`，
> 脚本侧 op 队列，SKILL §5.1，实验性）· **builtin（本文，agent 手动执行）**。
> 宿主支持 IAB 就优先 IAB（保住自动化）；IAB 不稳（见 SKILL §5.1 已知失效）再回退 builtin。

| | bsk（默认推荐） | builtin |
|---|---|---|
| 自动化程度 | 全自动：orchestrator loop、写闸门、自动续窗、三时钟 | 手动：agent 按本规程逐步执行，判据照用 |
| 依赖 | bsk CLI + 浏览器扩展 | 无（用宿主自带的浏览器能力） |
| 状态机 / 写闸门 / 平台占用锁 | 有 | **没有**（见 §E 边界） |
| 适合 | 长跑项目、auto 模式、多任务 | 快速试跑、宿主不许装后台进程、临时环境 |

选择入口：SKILL §0.2 的首次激活弹窗。记录后可随时切换：
`python scripts/env.py --set-backend bsk|builtin`。

## B. 绑定（对应 SKILL §3，等价 `wa.py bind`）

1. 先取规格（唯一来源，别凭记忆写选择器）：

   ```bash
   python scripts/platforms.py spec <平台> --json   # URL 形态 / 选择器 / ttft_s / stall_s
   ```

2. **新对话**：用浏览器工具打开平台的 `new_chat_url`（SKILL §3.2.1：Gemini 是
   `gemini.google.com/app` 不是 home）。落点必须「无会话 id + 0 条消息」；
   被重定向回已有对话 = 拒绝，换新对话入口重试。
3. **归属门禁等价物**：绝不接管用户正在聊的对话。首次绑定只接受自己刚开的新对话。
4. **登录**：未登录就停下让用户登录（SKILL §3.1 原文适用：不代填凭证、敏感数据不进正文）。
5. 绑定信息记录到 `runtime/wa/builtin-log.md`（每行：时间 / 平台 / url / conv_id / 备注）。
   **不写 `.wa-state.json`**——那是 bsk 模式的状态机文件，混写会在切回 bsk 时错位。

## C. 发送（对应 SKILL §4.1，等价 `wa.py send`）

用浏览器工具对页面执行 JS（选择器从 spec 的 `sel` 取）：

1. **弹窗检查先行**：可见且面积 ≥24px 的 modal / 全屏遮罩 / 验证码 iframe → 停（等价 rc=10 风控）。
2. 焦点编辑器 → **全文一次写入**（`insertText` 覆盖式，不是 append；受控编辑器用
   Range + `execCommand('insertText')`）。
3. **写后校验字数**，不符重写一次；连字数都不对就别点发送。
4. 点发送后**三重判据确认**（任一）：消息数 +1 / 地址变化（出现 conv_id）/ 发送正文指纹
   出现在页面。三者都不满足 = **没发出去**（等价 rc=14），查弹窗，不记轮次、不等回复。
5. 每轮发送记录：时间、正文哈希、消息数基线 → `runtime/wa/builtin-log.md`。

## D. 等待与分诊（对应 SKILL §4.9.4，等价 `wa.py wait` / `triage`）

三时钟参数从 spec 取（`ttft_s` / `stall_s`；总超时仍 900s）。**判据与 bsk 模式完全一致**，
只是探测由 agent 的浏览器工具执行（`document.querySelector` / 文本采样）：

| 顺序 | 看什么 | 结论 | 动作 |
|---|---|---|---|
| 1 | 验证码 / 遮罩 / 限流文案 / 掉登录 | 风控 | **停下找人**；不重发不刷新 |
| 2 | 地址 / conv_id 变了 | 漂移 | 按 §B 重新绑定 + 贴项目现状摘要 |
| 3 | 停止按钮在、页面在涨 | 在生成 | 继续等，不动 DOM |
| 3b | 停止按钮在、子树 15s 不变 | 假生成 | 按一次停止再重发 |
| 4 | 回复计数涨了、正文有字 | 就绪 | 直接读 |
| 5 | 页面在涨、spec 选择器读不到 | 选择器失效 | 换 spec 里下一个候选选择器**只读复探**，不刷新 |
| 6 | 发的文字还在输入框 | 没发出去 | 按 §C-4 处理 |
| 7 | 全都不动、无风控提示 | 静默拒绝 | 按限流处理：等冷却或换平台 |

两条铁律照旧：**不刷新页面**（生成中刷新=丢回复）；**没分诊不重发**。

## E. 边界（builtin 模式刻意没有的东西，别假装有）

| 没有 | 后果 | 补法 |
|---|---|---|
| orchestrator 状态机 | 无 `loop --resume`、无轮次预算自动执行 | 手动循环（SKILL §4），轮次自己记在 builtin-log |
| 写闸门四步 | 无 dry-run/批准单机器化 | 授权范围仍按 SKILL §2.5 人工确认，写前自查 |
| 平台占用锁（rc=9） | 并发打架不会被拦 | **同一平台同一浏览器环境手动串行**；并行就错开平台 |
| 自动续窗 / 单窗口纪律断言 | 无 `ensure_session` / `windows` | 自己保证：一个对话一个 tab，用完关闭；不重复开 |
| `.wa-state.json` | 与 bsk 模式状态不互通 | 切回 bsk 后重新 `wa.py bind`（同地址） |

其余纪律（六条硬规则、失败两次换方案、反馈七段、三轮法则、留痕）**全部照用**——
builtin 改变的是「谁的手在键盘上」，不改变流程本身。
