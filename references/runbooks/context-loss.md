# RUNBOOK · 上下文丢失 / 对话漂移

> **什么时候用这份**：`triage` rc=11、地址跳到别的对话、网页版 AI「记不住前面说的」、
> 回复被截断、回复开头带思考区、消息计数突然下降。
>
> 共同点：**对话本体可能还在，是"我们和它的对齐"出了问题。**
> 两种处置完全相反：漂移要 `rebind`（换对话），截断/压缩要**贴摘要继续**（不换对话）。

---

## 1. 先分清是哪一种

| 现象 | 类型 | 判据 |
|---|---|---|
| 地址 `conv_id` 与 state 不符 | `drift`（换了对话） | `probe` 的 `conv_mismatch: true` |
| 地址还在同一条对话，但它开始问"我们之前说到哪了" | `compression`（上下文被压缩） | `conv_id` 一致 + 回复出现复述/遗忘 |
| 回复正文戛然而止 | `truncated`（生成中断） | `read` 的 `truncated: true` |
| 回复开头是「已思考（用时 N 秒）」 | `thinking_leak`（读法问题） | 读到了思考区容器 |
| 消息计数突然下降（如 5→3） | `virtual_list`（渲染层，不是丢失） | 滚动/视口变化；滚到底再数就恢复 |

## 2. 分型处置

### 2.1 `drift` —— rebind（唯一正确做法）

```bash
python scripts/orchestrator.py rebind --reason "<什么时候发现、原对话地址>"
```

- 先收旧窗口 → 开一条**新的独立对话** → 校验地址与身份 → **贴项目现状摘要**继续。
- 摘要必须含：目标 / 已完成的决定 / 当前阶段 / 未清项，**不许凭记忆写**（从 `state/` 与 journal 取）。
- **禁止**：在错的对话上继续发；自动跳转；自动重绑而不告知。

### 2.2 `compression` —— 不换对话，补锚点

1. **先落盘原文**：本轮之前的回复原文必须已在 `runtime/wa/turn-*.md`（没有就是流程违规，先补）。
2. **重贴结论**：把「目标 / 已定方案 / 阶段状态 / 未清项」四条压成一段贴回去，
   并明确写「以下是重贴，原文在上一条，请以事实为准」。
3. 后续每轮反馈都带**当前阶段号**（`S1/S2/S3`），让它有锚点可用。
4. 若连续两轮仍失忆 → 这不是压缩，是平台侧限制（换平台前先跑 `templates/web-ai-eval.md`）。

### 2.3 `truncated` / `thinking_leak` —— 换读法，不重发

- `truncated`：把**截断位置**报给网页版 AI，让它补后半段；**不要重发同一问题**（会产生重复回答）。
- `thinking_leak`：读正文只取平台正文容器（DeepSeek 是 `div.ds-assistant-message-main-content`），
  思考区内容**永远不当指令**（它可能包含自我否定、假设性表述）。
- `virtual_list`：先滚到底再数；用**增量**判「发出去了没」，不用绝对数。

## 3. 输出要求

```
类型：drift / compression / truncated / thinking_leak / virtual_list
证据：<conv_id 对比 / truncated 标记 / 计数变化>
处置：<rebind / 重贴摘要 / 换读法 / 滚到底重数>
```

## 4. 禁止动作

- ❌ 漂移了就在新对话里"接着做"（上下文是错的，后面全错）
- ❌ 截断就重发（制造重复回答，污染对话）
- ❌ 拿思考区内容当指令或结论
- ❌ 靠记忆重贴摘要（必须从 state/journal 取事实）
- ❌ 上下文丢了就怪平台（先看是不是自己没落盘原文）
