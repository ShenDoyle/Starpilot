# P1-B-T1 idle 计时机制六组对照测试设计

BRM P1-B · 只读设计（不启动/停止任何 daemon）
状态：送审稿 v1 · 2026-11-03 · 供 Web AI 裁定

## 1. 实验目的

裁定焦点：「必须证明哪些真实操作刷新 idle，不能把外部心跳当作 session 活动。」本组实验确定 daemon 的 idle 计时到底被哪些命令刷新，从而裁决 idle 治理方案（D 基线下 C 是否可启用）。

## 2. 隔离条件

继承 T0 隔离环境；`--session-idle 30s` 加速实验；每组实验独立 session（不混用）；对照实验期间**本机无其他 bsk 命令**（避免污染计时）。

## 3. 操作步骤（六组对照）

统一模式：起 session → 每 15s 发一次被测命令（30s idle 周期内两次）→ 持续 3 分钟 → 若 session 存活 = 被测命令刷新 idle（REAL_PASS「刷新」）；session 被回收 = 不刷新（REAL_PASS「不刷新」）。每组重复 2 次防偶发。

| 组 | 被测命令（周期 15s） | 判定目标 |
|---|---|---|
| G1 | 无（纯空闲） | 基线：30s 回收成立 |
| G2 | `session list` | 非动作命令 |
| G3 | `cooperate sync` | 协议命令 |
| G4 | `tab list` | 只读命令 |
| G5 | `evaluate "1+1"`（目标 about:blank） | 动作命令（真实业务动作的原型，无页面副作用） |
| G6 | `navigate about:blank`（往返） | 导航类动作 |

补充组（视 G 组结果）：G7 业务页面上 `evaluate`（验证与 about:blank 无差异）；G8 `session request --prepare`（预备令牌算不算活动）。

## 4. 观察指标

- 每组 session 存活时长（对照 30s 基线）。
- daemon 日志的 idle 回收记录时间戳（回收时刻是否≈最后命令+30s，可反推「最后命令是否重置计时」）。
- 被测命令自身的返回码/耗时（命令失败=该组无效，重跑）。
- about:blank 页面在 G5/G6 后的 DOM 是否残留变化（副作用审计）。

## 5. 预期结果（全部为待验证假设，NOT_TESTED）

| 组 | 预期 | 方案裁决含义 |
|---|---|---|
| G1 | 回收 | 基线成立 |
| G2/G3/G4 | 未知（**核心悬念**） | 任一刷新 → 方案 B 出现安全实现（非动作保活）；全不刷新 → B 永久出局 |
| G5 | 刷新（INFERRED） | 刷新 → C 可启用（真实动作=唯一活动源）；不刷新 → C 永久出局，D 唯一 |
| G6 | 刷新（INFERRED） | 同上；同时验证导航不误伤页面 |

**失败判据**：G1 未在 30s±10s 回收 → idle 参数不生效，全部结果作废，检查 daemon 启动参数后重跑；G5/G6 出现非预期页面副作用（页面文本/DOM 变化）→ 该命令从「无副作用保活候选」中除名。

## 6. 清理方法

每组结束立即 `session stop`（或等 idle 自回收）；daemon 随 `--daemon-idle` 自灭；实验目录删除。

## 7. 业务环境保护

- 六组全部在实验 daemon + 独立 profile；G5/G6 只碰 about:blank。
- 补充组 G7 碰业务页面属**禁止**（改为实验环境内加载的本地测试页）——裁定「保活不能影响用户窗口」。
- 命令节奏固定脚本化（15s 定时器），禁止人工随意插命令。

## 8. 对 P1 设计的输出

产出「idle 刷新命令白名单表」（每项 REAL_PASS/REAL_FAIL）→ 直接决定 architecture 文档 §2 的方案组合最终形态；结果回写设计文档并送审。
